# AI_COLLABORATION.md

## 职责

本文件只定义 AI 与人工协作时的任务分级、授权升级、执行边界、证据口径、临时产物和收口方式。

本文件不定义项目架构、代码风格、运行命令、环境现状或单项需求的业务规则。

## 文档权威层级

- 强约束和授权边界以 `AGENTS.md` 为准。
- 架构红线以 `PROJECT_RULES.md` 为准。
- 工程风格以 `STYLE.md` 为准。
- 项目定位、当前已接通主链路、稳定运行摘要和文件地图以 `README.md` 为准。
- 启动、验证、Git、数据库和发布命令以 `DEV_WORKFLOW.md` 为准。
- 当前实现和运行事实必须按适用范围由代码、匹配测试、指定的当前事实文档和执行前只读核查支持；证据冲突时停止并报告。
- 当前需求的目标业务合同、范围、实施拆分和验收标准以对应需求文档为准；尚未实现或验证的目标不是当前事实。
- `docs/` 下其他需求、设计和阶段材料只用于按需追溯，不定义智能体规则，不得覆盖当前代码、测试或运行现场。
- 复杂 AI 过程材料不在仓库内落地；稳定结论回写到负责该事实的文档。

## 任务分级

项目可按实际删除不适用等级，例如没有数据库、真实联调、验证环境或线上发布时，不保留对应空壳；不得把删除某等级解释为放宽授权。

### 只读核查

允许：

- 读取文件、配置和日志。
- 搜索文本、列举目录、查看 Git 状态、差异和历史。
- 调用不会改变状态的查询接口。
- 在说明环境、库名和影响范围后执行数据库 `SELECT`。

不允许：

- 写文件或数据库。
- 执行迁移、数据修复、依赖安装或配置修改。
- 启动、停止或重启服务。
- 执行 Git 写操作、远端同步或发布。

默认交付格式：

- 只读澄清：结论、必要事实与证据、风险或未决项、下一步停点；无内容项省略。
- 只读修改计划：目标与不做、新增或修改文件及职责、实施顺序、验证范围与风险；输出后停在计划，不开始实施。

### 小改动

允许修改当前任务直接相关的代码、测试或文档，并运行本地匹配范围验证。

小改动不自动包含：

- 数据库写入、DDL 或迁移。
- 真实业务写接口、后台任务或跨系统端到端。
- 依赖安装、运行配置修改或服务状态变化。
- Git 提交、推送、验证环境发布或最终线上发布。

### 真实联调

以下任一行为都属于真实联调：

- 调用真实外部接口。
- 写非生产数据库或触发真实业务状态变化。
- 运行后台任务、浏览器自动化或跨系统端到端流程。
- 启动、停止或重启本地及非生产服务。

执行前必须说明：

- 环境和实际解析配置。
- 数据库、业务对象、接口和服务。
- 读写性质、预计影响量和隔离边界。
- 执行顺序、立即停止条件和证据要求。
- 已获得的逐次授权或受保护自动化预授权，以及未被授权的动作。

### 数据修复和迁移

数据库 DDL、DML、软删除、历史修复、回填、迁移和回滚计划不得由“小改动”或“真实联调”授权推导。项目可以把经审核、非破坏性的正式迁移预授权给受保护流水线；没有明确定义时默认逐次授权。临时 DDL/DML、破坏性迁移和数据修复始终单独授权。

执行前必须提供：

- 环境、库名、目标表和数据所有者。
- 精确筛选条件、预计行数和完整 SQL 或迁移入口。
- 备份或可恢复性事实；不能验证时明确风险。
- 执行后只读回查 SQL。
- 失败时的停止条件和现场保护方式。

未知现场不得直接执行所谓“回滚命令”；先只读核对当前状态，再由人工决定恢复方案。

### 验证环境发布

非最终环境的远端发布是独立任务等级，必须写明实际环境名称，不使用含糊的“部署一下”。授权可由本次人工批准，或由项目已定义的受保护流水线触发条件提供；两者都必须可审计。

至少满足：

- 开发源提交已通过项目规定的发布前验证门禁。
- 目标环境的代码或制品入口、工作区和实际配置身份正确。
- 记录 `validated_source_identity`、目标环境代码身份和部署制品摘要。
- 制品上传或晋级、目标状态变化、迁移或真实写入分别处于已授权范围。
- 发布后完成该环境适用的平台状态、smoke、可用性检查和约定业务验收。

### 最终线上发布

最终线上发布必须具备独立授权边界，较低风险环境的发布授权不得自动扩大为线上授权。项目可选择逐次人工批准，或把合并到受保护代码线、必需检查通过和环境保护规则共同定义为预授权；必须在 `AGENTS.md` 与 `DEV_WORKFLOW.md` 写清。

至少满足：

- 前置验证已经通过，并记录 `tested_source_identity`。
- 当前准备发布的源代码或不可变制品与 `tested_source_identity` 完全一致。
- 源代码、构建依赖、构建参数、版本化发布配置或制品发生变化时，重新执行前置环境发布和验收；环境级密钥和运行配置按目标环境独立校验，不要求跨环境相同。
- 最终环境的代码或制品入口、工作区和实际配置身份正确。
- 发布范围、远端状态变化和发布后证据已说明。
- 默认只做发布和只读可用性检查；后台任务、真实写接口和线上数据操作另行授权。

## 标准协作生命周期

### 开始前

非平凡任务开始前，用 3～5 行说明：

- 本次目标：用户最终可观察到的结果。
- 不做范围：容易顺手扩展但本次明确不做的事项。
- 完成标准：满足哪些可验证条件即可停止。
- 验证方式：计划运行的最小必要检查。
- 环境与影响：仅在涉及真实资源时说明。

如果存在多种会显著改变结果的解释，列出差异并请求确认；如果能从仓库事实安全确定，不把可自行核查的问题抛回用户。

### 需求文档判断

出现新功能、跨模块调用链、接口或表结构变化、多批次实施、真实联调或发布时，必须基于 `REQUIREMENT_DEVELOPMENT.md` 建立需求文档。

需求文档是稳定业务合同，不是过程日志。只有当前有效结论、确认决策、实施边界、验证证据和状态进入文档；聊天流水、探索命令和临时排查结论不得写入。

### 开发就绪门禁

进入编码前必须确认：

- 目标行为、废弃行为、不做范围和不得改变的既有行为已明确。
- 会改变实现结果的待确认项为“无”。
- 当前行为已经由代码、接口、数据或日志证据支持，而非仅凭猜测。
- 实际调用链和直接影响文件已界定。
- 需要的授权等级、环境和验证证据已明确。
- 开发前同步、工作区状态和环境身份门禁已按 `DEV_WORKFLOW.md` 通过。

任一项不满足时，继续只读核查或请求确认，不得用兼容分支、默认值或隐藏开关绕过。

### 执行中

- 只沿当前目标的直接调用链修改代码、测试和文档。
- 每个改动都应能对应需求目标或验收标准；不能对应的改动不做。
- 先完成最小可验证实施单元，再运行定向测试；通过后才进入下一单元。
- 查询、业务判断、外部调用、事务、状态回写和响应拼装按项目架构职责分离，不为减少文件数混合边界。
- 修改业务代码时同步核对项目规定的审计或可观测性、职责注释或稳定说明、匹配测试；不适用项也要在收口时说明原因。
- 修改导致 import、变量、方法或文档描述失效时，只清理本次改动产生的孤儿。
- 发现旁支问题时按下列规则处理：
  - 会阻塞当前需求、使匹配测试失败或导致数据错误：纳入当前范围并说明原因。
  - 不影响当前需求完成：记录为后续建议，不顺手修改。
  - 需要架构重构、接口扩展、兼容旧逻辑、批量清理或新的授权等级：停止并请求确认。
- 阶段性结论明确标注为事实、推断或未验证风险。
- 长时间任务应提供简短进展更新，但最终答案必须自包含，不依赖中间消息。

### 收口条件

同时满足以下条件时必须停止当前需求：

- 用户要求的行为已实现，或只读结论已经给出。
- 与改动风险匹配的验证已通过，或已明确说明不能验证的原因。
- 没有由本次改动直接引入的阻塞问题。
- 需求文档中的当前状态和最终实现一致。
- 剩余事项属于优化、清理、体验增强、架构改进或旁支风险。

满足收口条件后不得继续深挖旁支；只输出改动、验证、未验证、风险、Git 和发布状态。

### “继续下一步”的语义

用户说“继续”“下一步”或“继续下一步”时：

- 当前实施单元已达到收口条件：进入需求文档中已定义的下一单元；没有下一单元时询问下一目标。
- 当前实施单元未达到收口条件：只补齐当前最小闭环。
- 不得将“继续”解释为无限深入当前问题的细枝末节。

### 深挖熔断

默认在同一旁支连续排查超过 15 分钟、超过 5 轮命令或文件读取，或需要修改当前目标外模块时暂停。项目可在实例化时调整阈值，但必须保留熔断机制。

暂停时说明：

- 已确认事实。
- 卡住或不确定的点。
- 是否影响当前需求完成。
- 建议收口、继续核查还是拆成独立任务。

## 可选审查边界

AI 可在当前授权等级内自行增加只读检查，但只限：

- 当前任务直接相关文件、日志、配置和 Git 差异。
- 当前任务直接相关数据库 `SELECT`。
- 当前任务直接相关接口的无状态查询。

安装依赖、写数据库、执行迁移、调用写接口、运行后台任务、重启服务、修改远端状态或引入新的业务范围，必须先升级授权。

## 证据口径

### 小改动证据

- 本次修改文件。
- 关键差异及其对应需求。
- 定向测试和相关回归结果。
- 静态检查与 `git diff --check`。
- 审计或可观测性、职责注释或稳定说明、匹配测试三项核对结果。
- `git status`、提交和推送状态。

### 接口链路证据

- 入口接口、命令、事件或后台任务。
- 请求关键字段、业务主键和幂等标识。
- 响应关键字段和错误语义。
- service、client、模型或下游接口文件位置。
- 数据库只读回查结果。
- 日志事件、时间和链路追踪标识。

### 端到端证据

按项目实际裁剪以下证据，不得用 Mock 冒充真实联调：

- 页面或正式入口动作。
- 浏览器状态、Network 或 API smoke。
- 数据库只读回查。
- 审计日志或结构化业务日志。
- 关联 request_id、业务主键、批次、任务或事件标识。

证据必须记录环境、日期、提交或制品身份。其他环境的可用性检查不得替代需求规定的真实端到端，除非需求文档明确改变验收层级并获得授权。

### 数据变更证据

- 环境、库名、表名和执行授权。
- 实际执行的最终 SQL 或迁移身份。
- 执行前影响范围估算。
- 执行后只读回查结果。
- 未执行或失败项，以及当前现场状态。

### 部署证据

- `validated_source_identity` 和 `tested_source_identity`。
- 目标环境分支、提交或制品身份。
- 目标平台、轨道、工作负载或发布对象的实际状态。
- 实际运行配置或资源身份。
- 平台处理结果、smoke、可用性、遥测或日志中的适用证据。
- 是否执行了后台任务、迁移、写接口或数据操作。

## 临时产物

- 一次性排查脚本、临时 SQL、浏览器截图、Network 导出、日志副本和临时测试记录默认不提交。
- 复杂协作过程材料默认不进仓库；需要保存时由用户指定仓库外目录或外部工程。
- 可复用验证脚本只有在用途稳定、入口明确并有维护责任时才进入项目脚本目录。
- 清理临时产物不得删除用户未授权删除的文件。

## 收口输出

完成任务后必须说明：

- 改了什么。
- 验证了什么。
- 没有验证什么。
- 业务代码改动的审计或可观测性、职责注释或稳定说明、匹配测试核对结果；没有业务代码改动时说明不适用。
- 剩余风险是什么。
- Git 或版本控制状态，以及是否提交、推送或发布到任何目标环境。
