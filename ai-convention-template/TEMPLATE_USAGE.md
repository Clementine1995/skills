# TEMPLATE_USAGE.md

本目录是一套可复制到任意项目的 AI 协作治理文档模板，覆盖授权边界、架构红线、工程风格、任务分级、可执行命令和需求开发。本文件是模板包自身的使用说明，不复制进目标项目。

## 文件清单与角色

| 文件 | 角色 | 复制进目标项目 |
| --- | --- | --- |
| `TEMPLATE_USAGE.md` | 模板包使用说明与实例化清单 | 否 |
| `AGENTS.md` | AI 入口：最高优先级授权边界、禁止事项和文档索引 | 是 |
| `README.md` | 项目定位、主链路、运行口径、目录与文件地图 | 是 |
| `PROJECT_RULES.md` | 项目特有架构红线与验证映射 | 是 |
| `STYLE.md` | 工程风格：语言、命名、注释、测试和提交信息 | 是 |
| `AI_COLLABORATION.md` | 任务分级、协作生命周期、证据和收口 | 是 |
| `DEV_WORKFLOW.md` | 初始化、构建、验证、Git、数据库和发布的唯一命令来源 | 是 |
| `REQUIREMENT_DEVELOPMENT.md` | 需求文档标准、最小模板和完整模板 | 是 |

## 实例化步骤

1. 先按“项目类型选择”确定本项目需要保留的能力，再将除本文件外的 7 个文件复制到目标项目根目录。
2. 先填写 `README.md`，确定项目定位、负责与不负责范围、真实主链路、环境摘要和文件地图。
3. 填写 `AGENTS.md` 的授权边界、文档索引、发布授权模式和多智能体策略；删除不适用的可选文档引用。
4. 重写 `PROJECT_RULES.md`，只保留确实会造成架构破坏或业务事故的红线，并为每条红线填写可执行的验证映射。
5. 按团队真实约定修改 `STYLE.md`，不要机械复制示例语言、commit 前缀或禁用命名。
6. 裁剪并填写 `DEV_WORKFLOW.md`：删除不适用章节，写入真实命令、工作目录、影响说明、前置条件和成功标准；未替换的占位命令禁止执行。
7. 固定实际存在的环境、代码或制品身份、配置、数据库和外部资源边界，并验证 smoke、自检或健康检查能证明运行身份。
8. 只有存在复杂需求、跨模块改动、数据结构变化、真实联调或发布时，才使用 `REQUIREMENT_DEVELOPMENT.md` 建立需求文档；点状修复不为填满模板强行建档。
9. 只有存在多环境晋级或远端发布时，才填写发布拓扑、线上修复回流策略、已验收版本身份和发布异常后的只读核查入口。
10. 全局搜索 `{{...}}`，确认没有非预期残留；检查所有 Markdown 交叉引用均指向存在的文件和章节。
11. 核对根目录治理文档、当前事实文档和 `docs/` 追溯材料的权威层级，避免需求或阶段材料覆盖代码、测试和最新运行现场。

## 项目类型选择

先选择最接近的项目画像，再按实际情况增删章节；一个项目可以同时适用多个画像。

| 项目画像 | 通常保留 | 通常删除或简化 |
| --- | --- | --- |
| 纯库、CLI 或单模块工具 | `README.md`、`AGENTS.md`、`PROJECT_RULES.md`、`STYLE.md`、`AI_COLLABORATION.md`、最小化的 `DEV_WORKFLOW.md` | 常驻服务、健康检查、数据库、真实联调、环境发布和线上修复 |
| 前端或单体应用 | 基础运行、构建、自动化验证、项目架构红线和需求模板 | 不存在的后端服务、数据库、消息系统和多环境发布章节 |
| 后端或常驻服务 | 环境身份门禁、启动与停止、健康检查、可观测性、自动化验证 | 不存在的数据库、消息系统、发布目标和专项运行手册 |
| 涉及数据库或外部系统 | 数据库结构变更、数据修复、真实联调、外部资源边界和只读回查 | 项目没有的资源类型和操作入口 |
| 多环境发布或 CI/CD | 发布身份模型、晋级拓扑、发布后检查、未知现场处理和授权模型 | 不存在的验证环境、最终环境或直接修复入口 |

判断标准是“项目实际需要什么”，不是“未来可能需要什么”。不适用的章节、命令块、目录说明和占位符应一并删除。

## 实例化完成检查

完成后至少确认：

- `{{...}}` 只出现在明确允许保留的模板文件中，目标项目文档没有非预期占位符。
- `AGENTS.md`、`README.md`、`PROJECT_RULES.md`、`STYLE.md` 和 `AI_COLLABORATION.md` 的职责没有互相覆盖或冲突。
- `PROJECT_RULES.md` 的每条红线都有验证入口和通过标准。
- `DEV_WORKFLOW.md` 中的命令都能在指定工作目录、环境和身份下执行；不适用章节已删除。
- 需求文档只记录已确认的目标合同和证据，不把计划或未验证结果写成当前事实。
- 目标项目根目录没有复制 `TEMPLATE_USAGE.md`，除非项目明确需要保留模板维护说明。

## 适配不同项目类型

- 纯库、命令行工具或单模块项目：删除服务、发布、数据库和多环境章节；`README.md` 和 `DEV_WORKFLOW.md` 内均有对应删除提示。
- 没有数据库、CI/CD 或远端发布的项目：直接删除对应章节，不保留空壳。
- 范围小的需求：使用 `REQUIREMENT_DEVELOPMENT.md` 的最小需求模板，不为填满模板制造流程。
- 项目新增治理文档时，先在 `AGENTS.md` 的索引和权威层级中登记，再界定它负责的事实范围，避免形成第二套口径。

## 工具兼容

`AGENTS.md` 是所有 AI 工具的统一入口。若所用工具不识别 `AGENTS.md` 而要求其他入口文件（如 `CLAUDE.md`），把 `AGENTS.md` 的内容放入对应入口文件或在其中引用，保持单一口径，不维护两份边界。

## 模板维护

模板包自身的修改不自动进入已实例化项目；需要同步时由项目按差异评审后手动合并。
