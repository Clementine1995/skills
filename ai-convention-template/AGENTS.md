# AGENTS.md

## 职责

本文件是 AI 进入仓库后的第一入口，只保存最高优先级的授权边界、禁止事项和文档索引。

项目事实、架构、风格、协作流程和可执行命令分别由下列文档维护；不得在本文件重复形成第二套口径。

## 必读

进入仓库后，必须先完整读取：

1. `README.md`：项目定位、边界、主链路、环境摘要和文件地图。
2. `PROJECT_RULES.md`：项目特有且可验证的架构红线。
3. `STYLE.md`：工程风格、命名、注释和测试约定。
4. `AI_COLLABORATION.md`：任务分级、协作生命周期、证据和收口规则。

## 按需读取

- `DEV_WORKFLOW.md`：准备修改代码、启动或验证服务、执行版本控制、数据库或任何环境发布时读取；它是可执行命令的唯一来源。
- `REQUIREMENT_DEVELOPMENT.md`：新功能、跨模块改动、接口或数据结构变化、多批次实施、真实联调或发布任务开始前读取，并据此建立需求文档。
- `{{environment_status_doc}}`：核对易变化的目录、分支、配置、端口、数据库、容器、代理或远端资源现状时读取；没有独立环境现状文档时删除本项。
- `{{service_runbook_doc}}`：处理复杂独立服务、模型或专项部署验收时读取；没有专项运行手册时删除本项。

## 单一事实来源

- 强约束和授权边界以 `AGENTS.md` 为准。
- 项目定位、当前主链路和文件地图以 `README.md` 为准。
- 架构红线以 `PROJECT_RULES.md` 为准。
- 工程风格以 `STYLE.md` 为准。
- AI 协作、证据和收口以 `AI_COLLABORATION.md` 为准。
- 启动、验证、Git、数据库和发布命令以 `DEV_WORKFLOW.md` 为准。
- 单项需求的当前业务合同、范围、决策和验收标准以对应需求文档为准。
- 需求文档不得降低本文件、架构红线、环境隔离或发布门禁；发生冲突时停止并报告。

## AI 协作材料

- 仓库只保存稳定业务源码、测试、项目说明、需求合同、运行说明和必要验证入口。
- 不保存聊天流水、临时推理、重复审查稿或历史过程归档。
- 一次性脚本、临时 SQL、截图、日志副本和真实业务标识默认不提交；确需保留时由用户明确指定仓库外目录或稳定承接位置。

## 必须

- 对外默认使用最小必要说明：先给结论，只保留用户判断所需的关键证据、风险和下一步；不得因此减少内部检查和验证。
- 写文件前，先说明具体文件及每个文件的修改目标。
- 非平凡任务开始前，明确本次目标、不做范围、完成标准和验证方式；存在会改变实现结果的未决项时先澄清。
- 准备修改代码前，按 `DEV_WORKFLOW.md` 执行开发前基线同步、工作区检查和开发环境身份门禁；纯文档或只读任务只执行与风险匹配的最小检查。
- 修改前界定目标行为、废弃行为和不得改变的既有行为，只沿实际调用链修改当前任务直接相关的入口、服务、client、模型、数据结构、测试和文档。
- 选择能完成当前目标的最小方案，不为未来可能性新增抽象、配置、开关、兼容层或扩展点。
- 若旧逻辑已被本需求废弃，同步删除旧实现、旧分支、旧测试兜底、旧文档描述和相关测试，不保留新旧双轨。
- 只有用户明确要求兼容期时才保留旧逻辑，并在需求文档记录兼容范围、触发条件、观测方式和删除点。
- 删除、清空、覆盖、替换、移动、撤回或其他可能破坏现状的操作前，先只读确认精确目标、范围和影响；涉及历史数据、日志、配置、远端目录或未知现场时停止并说明。
- 说明项目事实、接口、问题或修改建议时，尽量提供文件和行号，并区分事实、推断和未验证风险。
- 涉及数据库、迁移、真实接口、worker、服务状态或远端资源时，先说明环境、对象、读写性质、影响范围、授权等级和验证证据。
- 每个受控环境必须使用已声明的工作区或制品、代码身份和配置；任何实际解析配置或健康检查身份不符时立即停止。
- 存在多个发布阶段时，各阶段必须分别表述、分别授权和分别验收；不得把较低风险环境的验证解释为最终线上验收。
- 多阶段发布必须追踪同一个已验证源提交或不可变制品；源代码、构建依赖、构建参数或版本化发布配置发生变化时，原验收失效。环境级运行配置和密钥可按环境不同，但必须通过各自身份门禁，且验收后未经批准的变化会使相关环境验收失效。
- 发布授权模式按 `{{release_authorization_model}}` 执行；可选择逐次人工授权或受保护流水线的预授权触发，但必须明确触发者、范围、审批、分支保护、环境保护和撤销方式。
- 修改后说明改了什么、验证了什么、没有验证什么、剩余风险、Git 状态以及是否提交、推送或发布。
- 多智能体策略按 `{{agent_collaboration_policy}}` 执行；实例化时必须改成项目真实规则，不得保留未决口径。

## 只读核查

- 只允许读取文件、搜索文本、查看 Git 状态和差异、读取日志和配置、调用无状态查询接口，以及执行数据库 `SELECT`。
- 不得写文件、写数据库、执行迁移、安装依赖、启动或停止服务、提交、推送或发布。
- 数据库只读查询前必须说明环境、库名和影响范围；数据库支持只读事务时，可在只读事务内执行 `SELECT`，最后用 `ROLLBACK` 结束查询事务。
- 上述 `ROLLBACK` 只表示结束只读事务，不是业务数据回滚；事务内禁止 DDL、DML 或任何状态变更语句。

## 禁止

- 未经用户明确授权，不执行 `git add`、`git commit`、`git push` 或 `git pull`。
- `git fetch` 和 `git merge` 只允许在用户已授权修改或发布的任务内，按 `DEV_WORKFLOW.md` 已实例化的开发前同步或发布门禁执行；不得临时发明其他合并方向。
- 禁止未经项目规则和用户授权改写共享历史、强推，或使用回滚分支指针、文件内容和业务状态的命令擅自修复流程错误；允许的 rebase、merge 和恢复策略必须在 `DEV_WORKFLOW.md` 明确实例化。
- 未经用户明确授权或项目已批准的受保护迁移流水线，不写数据库、不执行迁移；临时 DDL/DML、破坏性迁移和数据修复始终需要单独授权。
- 未经用户明确授权，不安装、升级或移除依赖，不修改环境变量、密钥或运行配置。
- 未经用户明确授权或项目已批准的受保护自动化策略，不启动、停止、重启或重新部署远端服务；真实写接口和远端后台任务仍按项目规则单独授权。
- 未经用户明确授权，不删除文件或目录，不清空日志、模型、上传物或历史数据。
- 不做与当前任务无关的顺手重构、清理、格式化、重命名、依赖调整、配置修改或接口扩展。
- 不为了降低改动量而留下废弃兼容代码、fallback、隐藏入口、临时映射、测试期兜底或永远不会执行的分支。
- 不把只读核查、本地验证或较低风险环境授权扩大解释为最终线上发布、线上写入或远端状态变更授权。
- 不在远端直接修改业务代码后绕过本地仓库和标准发布流程。

## 默认允许

- 读取当前任务直接相关的文件、目录、日志、配置和数据文件。
- 搜索文件、目录和文本。
- 运行只读命令，例如 `git status`、`git diff`、`git log`、目录列举和文本搜索。
- 解释实现、比较方案、指出风险和提出不改变状态的建议。

## 字符集

- 中文文档统一使用 UTF-8。
- 读取和写入文件时显式使用正确编码，避免平台默认编码造成乱码。
